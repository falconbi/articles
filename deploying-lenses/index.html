Deploying Lenses:
a separate path from Git

A Lens is a planning screen saved inside the TM1 model. It is not a cube, rule or process, so it does not travel with a normal model release. It has its own compare, approve and deploy flow.

01

What a Lens is

A Lens is a planning screen stored inside the TM1 model. It has HTML, settings, access rules, a title and a folder. People open it from the Lens app.

The Lens lives in the model under Applications/Governance/Lenses, next to the cubes and processes it uses.

WordWhat it means here
Change setThe record of saves one person made on one server.
Model releaseThe files built from one change set for one target.
SourceThe server you are copying Lenses from, usually DEV.
TargetThe server receiving Lenses, usually PROD.
Published / draftOnly published Lenses can ship. Drafts are listed but cannot be selected.
FingerprintA short code calculated from a Lens’s content. Same content gives the same code.
BlockerSomething missing on the target that stops the deploy.
PlanThe list of Lenses to add, change or delete.
02

Why Lenses use a separate path

A normal model release moves cubes, dimensions, rules, processes, chores, views and subsets. TM1 Git knows how to save and restore those objects. Lenses are different: they are application documents stored in the model.

Keeping them separate is deliberate. A model release should not fail because a screen changed. A Lens deploy should not ship a cube change. Both use the same target lock.

03

Compare source and target

Lens deploy starts with Compare. The IDE reads every Lens on the source, calculates a fingerprint for it, and compares that with the target.

The fingerprint covers the Lens content: name, status, description, folder, title, icon, colour, image, settings and HTML. It ignores version, timestamps, owner and creation details. Saving the same content twice still matches.

Lenses that exist only on the target are listed separately. They are not deleted automatically. You choose whether to delete one.

04

Blockers

A screen only works if the target model can run it. For every new or changed Lens, the IDE checks the cubes it writes and the processes it runs.

If a cube or process is missing on the target, that Lens is a blocker. The plan cannot be approved or deployed until the target has it. Ship the model objects first, then the screen that uses them.

05

Approve the exact content

Review shows the counts: new, changed, same and draft. It also shows blockers and target-only Lenses. New and changed published Lenses are selected by default. Deletions are off by default and must be ticked.

Approval records the approver, the note, the source and target, the fingerprint of each Lens, the plan fingerprint and the approved delete list.

Approval is for those exact Lenses. If any approved Lens changes after approval, or the plan changes, the deploy refuses. Run Compare again and approve again.

06

Deploy, check and record

Deploy takes the same target lock as a model deploy. It then follows a fixed order:

  1. Lock the target.
  2. Read the source again. Check every fingerprint against the approved one.
  3. Save each approved Lens with its settings, title, folder, icon, colour, image and HTML.
  4. Read each Lens back. Check the fingerprint again. A mismatch fails that Lens.
  5. Delete only the target-only Lenses you approved.
  6. Record each Lens result and delete in the target’s Lens deploy history.

There is no hidden rollback. If a deploy is wrong, fix the Lens on the source, compare again, approve the new content and deploy again. The history shows what actually landed.

07

The Lens deploy checklist

  1. Publish first. Drafts are never shipped.
  2. Ship the model objects first. A Lens that needs a missing cube or process is a blocker.
  3. Read the plan. New, changed, same, draft, blockers, target-only deletes.
  4. Approve the exact content. Approval is for those fingerprints, not “the latest”.
  5. Do not change anything after approval. If something changes, compare and approve again.
  6. Check the history. Confirm each Lens shipped and any approved deletes happened.
